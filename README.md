# Digital Speed — Claude Code Skill Library

The company-wide library of [Claude Code](https://code.claude.com) skills that Digital Speed employees can install, use, and contribute to.

**Audience**: Digital Speed employees using Claude Code.
**Maintainers**: Repo admins (merge rights). Everyone else contributes via pull requests.

---

## What is this?

A skill is a reusable instruction set — a `SKILL.md` file with YAML frontmatter (`name` + `description`) — that Claude Code loads on demand when a user's request matches the skill's description. Skills let Claude perform specialised tasks without re-explaining the steps each time: following a team convention, driving an internal CLI, generating a branded document, running a workflow across services.

This repo gathers every skill Digital Speed has vetted into one place, so any employee can pull the same toolkit into their own Claude Code setup. Use them to move faster on client work, automate repetitive workflows, and stay consistent with how the company does things (brand voice, Jira hygiene, Figma-to-code translation, Google Workspace operations, and more).

If a skill that would help you doesn't exist yet — write one and open a PR. That is the intended loop.

## Prerequisites

- [Claude Code](https://code.claude.com) installed and authenticated.
- Node.js 18+ (for `npx skills …`).
- Git.

## Quick start: install these skills into your Claude Code

Installing into the **project you are currently in** (commits into `./.claude/skills/`, shared with the team working on that project):

```bash
npx skills add digitalspeed/claude-code-skillset
```

Installing **globally** (available in every project on your machine, stored in `~/.claude/skills/`):

```bash
npx skills add digitalspeed/claude-code-skillset -g
```

Pick specific skills only:

```bash
# List everything in the repo first
npx skills add digitalspeed/claude-code-skillset --list

# Install one or a few
npx skills add digitalspeed/claude-code-skillset --skill brand-persona --skill jira

# Install all, skip prompts (good for CI and onboarding scripts)
npx skills add digitalspeed/claude-code-skillset --all -a claude-code -y
```

### Other useful commands

| Command | What it does |
|---------|-------------|
| `npx skills list` | Show skills already installed (`-g` for global only) |
| `npx skills find <keyword>` | Search installed skills |
| `npx skills update` | Pull the latest version of installed skills |
| `npx skills remove <name>` | Uninstall a skill |
| `npx skills init <name>` | Scaffold a new `SKILL.md` |

### Install locations (Claude Code)

| Scope | Path | When to use |
|-------|------|-------------|
| Project | `./.claude/skills/` | Shared with everyone on that project's repo |
| Global | `~/.claude/skills/` | Available across all your local projects |

Installs default to **symlinks** (one canonical copy, easy to update). Pass `--copy` if you need independent copies.

## Using a skill

Once installed, Claude Code loads skills automatically based on their `description`. You don't have to invoke them manually — just describe what you want to do. If a skill's description matches, Claude will use it.

You can also trigger a skill explicitly by typing `/<skill-name>` in Claude Code (e.g. `/brand-persona`, `/jira`).

Run `/help` in Claude Code or `npx skills list` to see what's available in your current session.

## Repository layout

Three directories hold skills, each with a different role:

| Directory | Purpose | Edit directly? |
|-----------|---------|----------------|
| `skills/` | First-party `gws-*` skills — our wrappers around the in-house `gws` Google Workspace CLI. | **Yes** — this is where we author. |
| `.claude/skills/` | Skills for Claude Code at the project level. Sourced from upstream repos. | **No** — vendored, overwritten on sync. |
| `.agents/skills/` | Mirror of `.claude/skills/` for agent harnesses that read from `.agents/`. | **No** — vendored, overwritten on sync. |

`skills-lock.json` pins every vendored skill to its upstream source repo (`anthropics/skills`, `vercel-labs/agent-skills`, `softaworks/agent-toolkit`, `digitalspeed/ai-skills`, `vercel-labs/skills`) with a content hash. To change a vendored skill, update it upstream and re-sync — do not patch it here.

`docs/skills.md` is an auto-generated index of the `gws-*` family (Services / Helpers / Personas / Recipes). It's regenerated by `gws generate-skills`; don't hand-edit.

## Skill anatomy

Every skill is a directory with at least a `SKILL.md`:

```markdown
---
name: my-skill
description: One-line hook. Describe what it does AND when Claude should use it.
---

# My Skill

Instructions Claude follows when this skill is active.

## When to Use

Concrete scenarios where this skill is the right match.

## Steps

1. …
2. …
```

**The `description` field is the trigger.** Claude picks a skill by matching the user's request against descriptions — if the hook is vague, the skill won't fire when it should. Write descriptions like: *"Use when the user asks for a Jira ticket from a Figma design."*

### Optional frontmatter

```yaml
metadata:
  internal: true   # hides the skill unless INSTALL_INTERNAL_SKILLS=1
```

Use `internal: true` for work-in-progress skills you don't want teammates to install yet.

## Contributing

Anyone at Digital Speed can contribute. **The `main` branch is protected — only repo admins can merge PRs.** Your job is to open a clean PR; an admin will review and merge.

### Workflow

1. **Create a branch** off `main`. Follow the naming convention: `<type>/<scope>-<short-slug>` — e.g. `feat/gws-drive-bulk-rename`, `fix/brand-persona-tone`, `docs/readme-quickstart`.
2. **Author or edit a skill.** Only touch:
   - `skills/` for first-party `gws-*` skills.
   - `docs/skills.md` (regenerate with `gws generate-skills` where possible).
   - Root docs (`README.md`, `CLAUDE.md`).
   Do **not** edit `.claude/skills/` or `.agents/skills/` — those are vendored.
3. **Test locally.** Install your branch into your own Claude Code and confirm the skill triggers and behaves as expected:
   ```bash
   npx skills add ./ --skill <your-skill-name>
   ```
4. **Open a PR** into `main` using the format below. Request review from a repo admin.
5. **Iterate on feedback.** Admins merge when it's ready.

### PR format

**Title** — follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <short summary in imperative mood>
```

- **type**: `feat` (new skill), `fix` (bug in an existing skill), `docs`, `refactor`, `chore`.
- **scope**: the skill name (`gws-drive`, `brand-persona`, …) or area (`docs`, `repo`).
- **summary**: ≤ 70 characters, imperative (“add”, not “added”).

Examples:
- `feat(gws-drive): add bulk-rename recipe`
- `fix(brand-persona): tighten description to stop over-triggering`
- `docs(readme): document PR format for contributors`

**Body** — use this template (also saved as `.github/pull_request_template.md` if present):

```markdown
## What
Short description of the change.

## Why
The problem this solves or the workflow this unlocks. Link to the
Jira ticket, Slack thread, or incident if relevant.

## How to test
Step-by-step so a reviewer can verify the skill in Claude Code:
1. `npx skills add <branch> --skill <name>`
2. In Claude Code, ask: "<the prompt that should trigger this skill>"
3. Expect: <what should happen>

## Checklist
- [ ] `SKILL.md` has a clear `description` that states *when* to use the skill.
- [ ] Tested locally in Claude Code.
- [ ] Updated `docs/skills.md` if adding a new `gws-*` skill.
- [ ] No changes to `.claude/skills/` or `.agents/skills/` (vendored).
```

### Writing a good skill

- **Description is everything.** It is the only signal Claude uses to pick your skill — lead with the trigger scenario.
- **Be specific.** "Use when the user wants X" beats "This skill handles X".
- **Keep `SKILL.md` short and scannable.** Move long reference material into sibling files (`references/`, `templates/`, `scripts/`) and link to them.
- **Name in lowercase kebab-case.** Group related skills with a prefix (`gws-*`, `persona-*`, `recipe-*`).

Run the `skill-judge` skill on your draft to get feedback before opening the PR:
```
/skill-judge path/to/skills/my-new-skill
```

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `No skills found` after install | Confirm the repo contains a `SKILL.md` and that its frontmatter has both `name` and `description`. |
| Skill doesn't trigger in Claude Code | Description is probably too vague. Rewrite it to state the *trigger scenario*, then `npx skills update`. |
| Skill installed but not listed | Was it marked `metadata.internal: true`? Set `INSTALL_INTERNAL_SKILLS=1` to see internal skills. |
| Permission errors on install | Check write access to `~/.claude/skills/` (global) or `./.claude/skills/` (project). |

## Environment variables

| Variable | Effect |
|----------|--------|
| `INSTALL_INTERNAL_SKILLS=1` | Show and install skills marked `internal: true`. |
| `DISABLE_TELEMETRY=1` / `DO_NOT_TRACK=1` | Disable `npx skills` anonymous usage telemetry. |
