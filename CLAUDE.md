# CLAUDE.md

Guidance for Claude Code when working in this repository. See [`README.md`](./README.md) for the full overview, install/usage, and contributor workflow — this file only covers what you need to operate safely inside the repo.

## Context

Digital Speed's skill library for Claude Code — a collection of `SKILL.md` packages, **not** a runnable application. There is no build, test, or dev server to execute.

## Directories — what is editable

| Directory | Editable? | Notes |
|-----------|-----------|-------|
| `skills/` | Yes | First-party `gws-*` skills. Author here. |
| `.claude/skills/` | **No** | Vendored from upstream; pinned by `skills-lock.json`. Changes get overwritten on sync. |
| `.agents/skills/` | **No** | Mirror of `.claude/skills/` for non-Claude harnesses. |
| `docs/skills.md` | **No** | Auto-generated by `gws generate-skills`. |

To change a vendored skill, modify it in its upstream repo and re-sync — do not patch it here.

## Authoring `gws-*` skills

- **Read `skills/gws-shared/SKILL.md` first.** It defines auth, global flags (`--format`, `--dry-run`, `--sanitize`), and CLI syntax (`gws <service> <resource> [sub-resource] <method>`). Defer to it rather than restating shared flags in individual skills.
- Follow the four-tier structure already in `skills/`: **Services** (`gws-drive`, …), **Helpers** (`gws-*-send`, …), **Personas** (`persona-*`), **Recipes** (`recipe-*`).
- After adding a skill, regenerate `docs/skills.md` with `gws generate-skills` if available locally.

## Writing `description` fields

The `description` frontmatter is the only signal Claude uses to match a skill to a user request — keep it tight and trigger-focused (*when* to use, not just what it does). Reference shapes:
- `.claude/skills/template-skill/SKILL.md` — minimal skeleton.
- `.claude/skills/skill-judge/SKILL.md` — evaluation criteria for authoring or reviewing.
